## Adopt / avoid decisions

- **Adopt with attribution when implemented:** official MCP server's schema validation, parameterized inputs and read-only query boundary (MIT); Skills' safe query/Compose practices (MIT); GraphRAG-SDK's provenance and abstention concepts (Apache-2.0). Reimplement; do not paste large blocks.
- **Use FalkorDB as the actual graph system:** native WCC, PageRank, betweenness and shortest/weighted-path procedures are present in the reviewed core tests. Do not treat an in-memory fallback as a successful FalkorDB run. Confirm exact names/config against the pinned event image.
- **Use competitor submissions only as benchmarks:** Syndicate is the closest fraud-ring scenario and provides useful motif/verification ideas, but its code is unlicensed and must not be copied. Its seed's `batch_execute` does not actually batch the queries. AEGIS is an incident-response graph, not financial fraud; its README's GraphBLAS claim is not borne out by the reviewed centrality implementation, which constructs a NetworkX graph from all database nodes/edges.
- **Do not add broad/unclear-license dependencies:** no QueryWeaver, text-to-Cypher or competitor code; no paid LLM integration by default. Ask the project owner before adding a paid API or a provider likely to incur cost.
- **Keep the existing UI:** preserve React/Vite as the prototype and build a separate Streamlit + PyVis judge path during the event. The separate app is additive; it is not a replacement migration.
- **Ground every result:** tool outputs and investigator verdicts must expose supporting graph IDs plus Cypher/algorithm provenance, and return an explicit “insufficient evidence” response rather than inventing an answer.
